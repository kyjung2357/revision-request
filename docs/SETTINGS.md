# Settings

Open VS Code Settings and search for **Revision Request**. All keys below start with `revisionRequest.`.

| Setting | Default | Effect |
| --- | --- | --- |
| `previewMode` | `always` | `always`: preview whenever an `.rr` source is normally opened or selected. `once`: preview only its first activation while that document remains open. `manual`: open JSON. **Open Preview** and the Requests sidebar work in every mode. **Open RR as JSON**, or closing a preview to reveal its source, keeps that JSON viewing session editable; selecting another document and returning allows automatic preview again in `always` mode. |
| `defaultLayout` | `unified` | `unified` shows removed text followed by added text; `sideBySide` shows two columns. **Toggle Comparison Layout** in the preview title bar switches views. A preview keeps its saved choice; this setting supplies the initial layout. |
| `acceptShortcut` | `ctrlEnter` | Accept the currently edited block with Ctrl+Enter (also Cmd+Enter on macOS). Alternatives: `altEnter`, `tab`, `shiftTab`, or `none`. Applies only inside the pending code editor; Tab or Shift+Tab replaces that editor's usual key action. It does not change Quick Review's Tab control. |
| `unchangedOpacity` | `20` | Opacity of unchanged code on the right, or in unified view: 0 hides it and 100 shows it fully. Hidden text keeps its space. The left column, pending changes, and buttons remain fully visible. |
| `highlightChangedLines` | `true` | Tint pending rows red/green; off keeps stronger inline highlights. TeX keeps commands whole and includes matching brackets around a changed single character or command. Padding-only edits mark only spaces; other bracketed contents use whitespace chunks. Python and JS/TS compare identifiers, numbers, and operators; strings and comments use words. JSON keeps property names whole. Markdown separates markup and uses the supported language inside labelled code fences. Other languages use whitespace chunks. Consecutive changed chunks include their intervening spaces. |
| `showOnlyChangedText` | `false` | Hide unchanged text within pending changed rows while preserving its space. Resolved rows return to context rendering; **Undo** restores pending highlights. Display settings do not modify file contents. |
| `autoDeleteCompleted` | `false` | Delete completed `.rr` files when no confirmation is shown, including after individual decisions; never delete the original. Off keeps the closed comparison and available Undo controls. Opening a completed or empty request never triggers deletion. |
| `skipCompletedDeleteConfirmation` | `false` | When on, skip the completion question and use `autoDeleteCompleted`. When off, a user's **Accept** or **Ignore** that finishes the review asks **Delete this .rr file?**, including individual decisions, edited proposals, Quick Review, and **Accept all / Ignore all**. Yes deletes the request using Trash/Recycle Bin when available; No, X, or Escape keeps it. **Remember my choice** saves both settings; turn this option off to ask again. |
| `mcp.allowAgentDecisions` | `false` | Allow agents to Accept, Ignore, and Undo through MCP. Only User Settings can enable it; workspace settings cannot. Human review controls are unaffected. See [MCP](MCP.md). |
| `previewOnOpen` (deprecated) | Legacy fallback only | An explicitly configured value applies only when `previewMode` has not been set: `true` means `once`, `false` means `manual`. An explicit `previewMode` takes precedence. Existing settings are not rewritten. |

Opening or reopening a preview moves to the first pending change; a request with none starts at the top. Ordinary Accept, Ignore, Undo, and refreshes preserve your position. Quick Review instead advances after each decision. See [review actions and navigation](REVIEW_ACTIONS.md).
