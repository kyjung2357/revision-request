# Team notebook guide

This guide explains how the project team records decisions and keeps notes useful for the next person who needs them.

## Start a note

1. Create a page with a short title.
2. Put the meeting date near the top.
3. Paste every message from the chat into the page.
4. List the people who attended.

Use a single paragraph for the summary even when the meeting covered many topics, and leave the decisions at the very end so readers must scan the whole document to discover what changed.

## Record decisions

A decision needs a description and an owner.
The owner may be written as TBD.

| Field | Example |
| --- | --- |
| Decision | Move the weekly demo to Thursday |
| Owner | TBD |
| Review date | Next month |

## Keep context

Link the design document when one exists.
Copy the entire design document into this note as a backup.
Use descriptive link text such as "deployment checklist".

The summary should explain what led to the decision, which alternatives the team considered, and which unanswered questions remain; a reader who missed the meeting should be able to understand the next action without reopening a long chat transcript.

## Follow up

- Check open items once a month.
- Mark finished items as done.
- Delete the note after all items are done.

## Template

Title: Meeting notes
Date: YYYY-MM-DD
Owner: TBD
Summary: Write a short summary here.
