# Team decision notebook

This guide explains how the project team records decisions and keeps notes useful for the next person who needs them.

## Start a note

1. Create a page with a short title.
2. Put the meeting date near the top.
3. List the people who attended.

Use a short summary for each topic and put the decisions near the top, so a reader joining the project can find the outcome, its owner, and the next action without reading the full meeting history or guessing which earlier discussion is still current.

## Record decisions

A decision needs a description, a named owner, and a review date.

| Field | Example |
| --- | --- |
| Decision | Move the weekly demo to Thursday |
| Owner | Mina |
| Review date | 2026-11-17 |

## Keep context

Link the design document when one exists.
Use descriptive link text such as "deployment checklist".
Include a heading or section link when the document is long.

The summary should explain what led to the decision, which alternatives the team considered, and which unanswered questions remain, and what evidence would cause the team to revisit the choice; a reader who missed the meeting should be able to understand the next action without reopening a long chat transcript.

## Follow up

- Check open items at the next weekly meeting.
- Mark finished items as done.
- Link the result from each completed item.
- Archive the note after all items are done.

## Template

Title: Decision and next action
Date: YYYY-MM-DD
Owner: Name the person responsible
Summary: Write a short summary here.

Next review: YYYY-MM-DD

Keep the note in the shared project folder so the next meeting can start from the recorded decisions.
